# PREACT-digital

This repository contains the data preprocessing, feature engineering, and machine learning pipeline for the **PREACT-digital** subproject (SP6) within the [FOR5187 PREACT](https://www.forschungsgruppe5187.de/) research unit. The project processes digital phenotyping data — wearable sensor streams (heart rate, sleep, steps, GPS, ECG) and Ecological Momentary Assessment (EMA) questionnaires — from psychotherapy patients, transforming raw exports into daily-aggregated feature sets for treatment outcome prediction.

> **Note:** This codebase is a continuation of the [leona-ha/tiki_code](https://github.com/leona-ha/tiki_code) repository (developed and used for the JITAI paper). The preprocessed outputs generated by this pipeline serve as the foundation for downstream modeling in:
> - [leona-ha/for_baseline_prediction](https://github.com/leona-ha/for_baseline_prediction)
> - [leona-ha/for_longitudinal_prediction](https://github.com/leona-ha/for_longitudinal_prediction)

## Environment Setup & System Requirements

### Python Environment

The project uses **Python 3.13**. Create a conda environment and install dependencies with pip:

```bash
conda create -n preact python=3.13 -y
conda activate preact
pip install -r requirements.txt
```

### Environment Variables (.env)

The project loads custom path configurations and API keys from a `.env` file located at the repository root. You can set this up by copying the template file `.env.example`:

```bash
cp .env.example .env
```

And then adjusting the variables inside `.env`:

```env
# The base directory path containing the datasets (raw/, preprocessed/, backup/, redcap/)
# Fallback default: /sc-projects/sc-proj-cc15-preact/SP6
TIKI_BASE_PATH="/sc-projects/sc-proj-cc15-preact/SP6"

# Google Sheets ID for the project metadata sheet
TIKI_PROJ_SHEET="your_google_sheets_id_here"

# TODO credentials
# Fallback default: /home/leha18/tiki_code/notebooks/tiki-399609-b68b5ade4dfb.json
TIKI_CREDENTIAL_PATH="/path/to/your/google-credentials.json"
```

These values are also mirrored in `server_config.py`, which provides hardcoded fallback paths used by the pipeline scripts.

### Raw Passive Data Schema (`epoch_part*.csv`)

Each row represents one sensor event:

| Column           | Type               | Description                                               |
|------------------|--------------------|-----------------------------------------------------------|
| `customer`       | string             | Participant ID (first 4 chars used as short ID)           |
| `startTimestamp`  | ISO-8601 / epoch ms | Event start time (UTC)                                   |
| `endTimestamp`    | ISO-8601 / epoch ms | Event end time (UTC)                                     |
| `timezoneOffset` | int                | Device-reported timezone offset (minutes from UTC)        |
| `type`           | string             | Sensor modality — e.g. `HeartRate`, `SleepDeepBinary`, `Latitude`, `Longitude`, `StepCount`, `ActivityType` |
| `doubleValue`    | float              | Floating-point payload (e.g. HR in bpm, GPS coordinates)  |
| `longValue`      | int                | Integer payload (e.g. step count, activity type code)     |
| `stringValue`    | string             | String payload (used for legacy ECG JSON data)            |

### EMA Data

EMA questionnaire responses are exported alongside passive data inside each `export_tiki_<DDMMYYYY>/` folder across five CSVs (`questionnaireSession`, `answers`, `choice`, `questions`, `questionnaires`). They are joined during preprocessing. A Google Sheets monitoring document provides participant metadata (pseudonym, study version, EMA start dates).

## Preprocessing & Aggregation Pipeline

The pipeline is made up of numbered scripts in `src/scripts/`. Run them in order — the number prefix indicates the sequence. Each script reads its input from the outputs of the previous step.

### Pipeline Overview

```
create_backup.py ──► 01_Data_Preprocess.py ──┬──► 02_Aggregate_All_Passive.py
  (historical CSVs      (merge + clean)      │       (daily sensor features)
   → unified Parquet)                         │
                                              ├──► 02gps_Aggregate_GPS.py
                                              │       (daily GPS features)
                                              │
                                              └──► 06_ECG_Preprocess.py
                                                      (HRV features)
```

### Step-by-Step

#### `create_backup.py` — Build unified historical backup

> **Note:** This script exists because data was obtained incrementally throughout the ongoing study — each export only contained new records since the last pull, and formats varied across collection periods. If you are starting from scratch with a single complete data export, you can **skip this step** and feed your data directly into `01_Data_Preprocess.py`.

| | |
|---|---|
| **Input** | Historical CSVs from `backup/first_backup/` + incremental exports from `raw/tiki_backup_files/` |
| **Output** | `preprocessed/backup_passive_05052025.parquet` |

Compiles all historical CSV exports into a single, deduplicated Parquet file. Handles mixed timestamp formats (ISO-8601 strings and epoch milliseconds), enforces a consistent schema, and processes data in 1M-row chunks to manage memory.

---

#### `01_Data_Preprocess.py` — Main data cleaning & preparation

| | |
|---|---|
| **Input** | New export CSVs (`epoch_part*.csv`) + historical backup (`.parquet`) + EMA CSVs + Google Sheets monitoring data |
| **Output** | `backup_passive_recent.feather` (cleaned passive data) + cleaned EMA DataFrame |

This is the main preprocessing entry point. It:

1. **Passive data**: Reads the latest export, merges with the historical backup (deduplicating the overlap), unifies `doubleValue`/`longValue` into a single `float_value` column, and infers timezone offsets using a [multi-stage resolution strategy](src/preprocessing/infer_timeoffset.py) (GPS offsets → neighbor interpolation → activity logs → Berlin DST fallback).
2. **EMA data**: Joins the five EMA CSVs together, assigns study phases (baseline / t20 / post), maps item codes, calculates coverage metrics, and flags weekends/seasons.
3. **Metadata**: Merges with Google Sheets monitoring data to attach `for_id` and `study_version` to each participant.

---

#### `02_Aggregate_All_Passive.py` — Daily passive sensor aggregation

| | |
|---|---|
| **Input** | `raw/backup_passive_recent.feather` |
| **Output** | `preprocessed/passive/daily/daily_aggregated_all_passive.feather` + per-modality `.parquet` files |

Aggregates cleaned passive sensor data to **one row per participant per day**. Each modality is aggregated independently, then merged on `[id, local_day]`:

| Modality     | Features produced                                                                                      |
|--------------|--------------------------------------------------------------------------------------------------------|
| **Sleep**    | Total duration, sleep efficiency, awakening count, insomnia/hypersomnia flags, sleep stage %s (deep/light/REM), onset/offset cosine-sine encodings |
| **Heart Rate** | Mean, std, min, max, skew, kurtosis; time in resting (<60 bpm), moderate (60–100), vigorous (≥100) zones; nighttime HR (20:00–06:00); sleep HR |
| **Steps**    | Daily total step count, hourly distributions                                                            |
| **Activity** | Minutes per activity type (e.g. sleep, walking, running, cycling)                                      |
| **Elevation** | Daily elevation change metrics                                                                         |
| **Floors**   | Daily floor count metrics                                                                              |

> **Debug mode:** Pass a debug flag to subset to a few participants and write outputs to `./tmp/` instead.

---

#### `02gps_Aggregate_GPS.py` — Daily GPS feature extraction

| | |
|---|---|
| **Input** | `raw/backup_passive_recent.feather` (Latitude + Longitude modalities) |
| **Output** | `preprocessed/passive/daily/daily_gps_metrics.feather` |

Extracts daily location features per participant:

| Feature                | Description                                              |
|------------------------|----------------------------------------------------------|
| `total_distance`       | Total Haversine distance traveled (meters)               |
| `entropy`              | Location entropy across visited clusters                 |
| `n_unique_clusters`    | Number of distinct places visited                        |
| `pct_time_at_home`     | Proportion of day spent at the home cluster              |
| `pct_time_transition`  | Proportion of time in transit (speed ≥ 1.4 m/s)         |
| `gps_coverage_*`       | Data quality metrics (points per hour, max gap duration) |

Home location is identified via DBSCAN clustering on nighttime (23:00–06:00) stationary GPS points.

---

#### `06_ECG_Preprocess.py` — ECG signal processing

| | |
|---|---|
| **Input** | Old format: `tiki_backup_*.csv` (JSON-encoded ECG strings) · New format: `*_Nokia_300.csv` (300 Hz voltage) |
| **Output** | `.parquet` files with ECG / HRV features |

Handles two raw data formats from different collection periods. Parses raw voltage traces, applies bandpass filtering, detects R-peaks, and computes heart rate variability (HRV) features using NeuroKit2.

---

### Data Cleaning Rules

The pipeline enforces these quality filters:

| Rule                   | Threshold                  |
|------------------------|----------------------------|
| Heart rate bounds      | Valid range: 30–220 bpm    |
| Step rate limit        | Max 200 steps/minute       |
| GPS speed filter       | Stationary < 1.4 m/s      |
| GPS inter-sample gap   | Capped at 12 hours         |
| Nighttime HR window    | 20:00–06:00                |
| GPS home detection window | 23:00–06:00             |
| Missing data sentinel  | `-1` for unmapped EMA sensor values |

### Preprocessing Modules

The scripts above import shared logic from `src/preprocessing/`:

| Module              | Key functionality                                          |
|---------------------|------------------------------------------------------------|
| `aggregation.py`    | Sleep session detection, daily HR/sleep/step aggregation   |
| `gps_features.py`   | Haversine distance, DBSCAN clustering, home extraction, location entropy |
| `ema_mappings.py`   | Map overlapping sensor events onto discrete EMA time blocks |
| `ema_features.py`   | Classify EMA score changes (improvement / deterioration)   |
| `infer_timeoffset.py` | Multi-stage timezone and DST offset inference            |
| `missing_data.py`   | Missingness summaries and daily data availability metrics  |
| `redcap_features.py` | Clinical outcome measures (BSI-GSI change, Reliable Change Index) |

## Quick Start

```bash
# 1. Clone the repository
git clone <repo-url> && cd preact_digital

# 2. Set up the Python environment
conda create -n preact python=3.13 -y
conda activate preact
pip install -r requirements.txt

# 3. Configure data paths
cp .env.example .env
# Edit .env to point to your data directory and credentials

# 4. Run the pipeline (in order)
python src/scripts/create_backup.py          # (optional) one-time: build historical backup
python src/scripts/01_Data_Preprocess.py     # clean & merge passive + EMA data
python src/scripts/02_Aggregate_All_Passive.py   # aggregate daily sensor features
python src/scripts/02gps_Aggregate_GPS.py        # aggregate daily GPS features
python src/scripts/06_ECG_Preprocess.py          # extract ECG/HRV features

# On the HPC cluster, use SLURM:
sbatch slurm/run_aggregation.sbatch
```
